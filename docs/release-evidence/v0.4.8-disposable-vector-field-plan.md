## Proof boundary

This is the public runbook for one disposable Cloudflare campaign. It names the
only test resources that may be used, but it contains no account identifier,
database identifier, hostname, route, credential, private file path, corpus
content, query, answer, or owner information. It authorizes no provisioning,
deployment, write, evidence capture, deletion, release, or customer action.

The campaign must use the exact frozen v0.4.8 package. A later executable,
dependency, migration, Worker bundle, runbook, or release-candidate change
invalidates the affected evidence. The adapter in
`operations/cloudflare-recovery-adapter.mjs` is the execution authority for the
recovery sequence. It can inspect an already-provisioned source and target,
export D1, restore the target, run `bootstrap-v2`, promote one reviewed active
Worker version, and verify health and the private release evaluation. It cannot
create, upload, route, or destroy resources.

The candidate now includes a fixed 6,001-document seeder, direct-D1 opening and
closing proof, private aggregate seed receipt, controlled mid-bootstrap hook,
aggregate observer, receipt consumer, and packaged split deployment dispatcher.
It also includes the exact D1-versus-provider Vectorize ID-set proof, processed
mutation watermark and Worker barrier binding, durable promotion-intent receipt,
source and final-target D1 deletion fingerprints, immutable evaluation audit
append, exact Worker identity and reviewed-generation proof, closed network
surface, exclusive campaign custody, continuous Vectorize mutation quiescence,
and receipt-bound source-before-target teardown. Those paths are locally
fixture-tested only. They do not prove a Cloudflare deployment or deletion and
cannot start this campaign until the exact commit and package pass their final
gates and each provider action receives its named approval.
The older `test/live/d1-release-field-gate.mjs` fixture proves only about 112
chunks and must not be run unchanged against either named campaign Brain.

The older combined producer remains unconditionally blocked. The packaged K0,
deployment, target-evaluation, teardown, and held closeout entry points preserve
the required causal order through separate commands:

1. preview and separately approve K0 local preparation of four fixed campaign
   Keychain values before any provider call;
2. complete A1 source provisioning and separately approved A3 target
   provisioning, then freeze the full recovery plan;
3. complete read-only source deployment preflight, record A2, deploy only the
   source, and seal its private receipt;
4. prove direct D1 is empty, ingest and replay exactly 6,001 documents, and
   seal the private seed receipt;
5. complete fresh A4 target preflight, upload the reviewed paused and active
   versions, deploy only paused, and seal the final deployment receipt;
6. complete recovery through active promotion, run the exact A12 target
   evaluation, and retain its private receipt;
7. complete separate source A13/A14 and target A15/A16 teardown ceremonies; and
8. keep A17 held until its exact field closure is separately accepted. Its
   implemented scope is only four campaign Keychain values, with retained
   evidence and the shared account token preserved.

Source and target preview are local-only. Each preflight uses Cloudflare GETs
and writes one owner-private receipt. A2 and A4 have different fingerprints and
cannot be combined or exchanged. Each mutation writes an ambiguity-safe private
journal before its provider boundary; an unconfirmed mutation refuses blind
retry. Final provider evidence uses two bounded reads and exact deployment-ID
readback. The dispatcher accepts no credential argument, uses the reviewed
macOS Keychain provider, and refuses Windows. These are packaged capabilities,
not field proof or authorization to run them.

`operations/cloudflare-disposable-deployment-transport.mjs` is the bounded
Cloudflare HTTP layer for provisioning and deployment and exposes no deletion
methods. The separate fixed teardown broker uses
`operations/cloudflare-disposable-teardown-provider.mjs` for its receipt-bound
A13 through A16 requests. Source and target semantic receipts bind exact Worker
identity, version, script etag, reviewed code generation, runtime, and bindings.
They prove the workers.dev identity,
previews and cache disabled, and zero routes, custom domains, schedules, tails,
extra Worker exports, assets, or logpush. Target preflight and final receipt also inspect
every traffic-bearing version of every non-campaign Worker and refuse if any
one binds either campaign D1 database or Vectorize index. The final target
receipt carries the exact same continuous Vectorize mutation-quiescence claim
as the recovery plan and is mandatory for recovery and teardown. The semantic
role records name the two role proofs `network_isolation` and
`worker_generation`; target semantics add `campaign_custody`. Both target

## Execution and interruption sequence

Use the same private paths, final deployment receipt, and all eight base
fingerprints on every run. The controlled interruption adds its ninth
fingerprint. The ordinary recovery stage checkpoints may first prove export,
restore, and security reconciliation by stopping after each named stage and
rerunning from the same state file. `--stop-after-stage` and the mid-bootstrap
test hook are mutually exclusive. The exact command shapes are documented in
`docs/RECOVERY.md`.

For the accelerated projection proof, start `rebuild_vectorize` while the
target still reports `paused-for-upgrade`. The reviewed controlled interruption
hook first performs a private fixed opening read, bracketed by the same paused
target identity. It must prove epoch 1, base count zero, protocol `NULL`, cursor
`NULL`, zero bootstrap batches and batch rows, zero outbox work, zero provider
vectors, and D1 documents/chunks/FTS equal to the verified restore. This opening
contract is separate from the aggregate observer's `bootstrap-v2` schema, which
is not broadened to accept an unopened protocol. Only then may bootstrap begin.
The interruption may fire only after the observer proves all of these together:

- protocol is exactly `bootstrap-v2`;
- the current epoch is a positive integer;
- the private cursor is nonempty and has advanced from its opening value;
- at least one durable `vector_bootstrap_batches` row exists for that epoch;
- at least one batch has durable queued, submitted, or confirmed progress;
- confirmed chunks are greater than zero and less than the exact D1 chunk total;
- D1 content and chunk aggregates still match the verified restore; and
- the target is still paused and the active version has not been promoted.

The private interruption snapshot records the epoch and a SHA-256 of the cursor,
plus aggregate batch, confirmed, pending, submitted, and provider counts. The
public receipt records only that the cursor was present and the before/after
comparison matched.

Resume with the exact same plan, state, manifests, encrypted provenance
artifact, wrapper, golden, owner-only field and deployment receipts and package,
exact lock-integrity-derived `wrangler 4.131.1` runtime closure, Node executable,
and inventoried synchronous module-resolution guard, eight base recovery approvals,
and the plan-bound ninth interruption approval. Before allowing new
bootstrap work, the observer must prove the same epoch, base count, high-water
mark, durable ledger cut, and same private cursor value recorded at
interruption. The adapter fsyncs that proof as a bound resume authorization
before the first resumed POST. Later retries may reconcile only monotonic
same-epoch progress, including a POST that committed remotely before its
response was lost. A new epoch, a missing or regressed cursor or ledger,
changed target identity, changed D1 corpus, changed high-water mark, or changed
Worker version stops the campaign.

At completion, the durable bootstrap ledger must show at least 3,001 actual
chunk admissions across its batch `row_count` values for the one epoch. This is
not a demand for more than 3,000 rows to be simultaneously pending: the reviewed
implementation deliberately limits the live bootstrap window to three batches
of 1,000. If an incident's acceptance text instead requires a simultaneous
backlog above 3,000, that is a different test and must receive its own reviewed
runner rather than being inferred from this campaign.

Only after the paused bootstrap is complete may the adapter promote the exact
reviewed active version. The adapter pages every non-null D1 vector ID and the
provider's complete Vectorize inventory, rejects duplicates, cursor loops,
extras, and omissions, and requires exact set equality. It brackets the Worker's
authenticated readiness barrier with stable processed-mutation watermark reads
and requires the same mutation ID. Complete paused parity is fsynced first as a
separate bootstrap promotion authorization. The adapter then persists the
private `.brain-recovery-target-promotion-intent-v1.json` receipt before the
deployment request. That receipt binds the exact ID set, watermark, Worker
barrier, active version, plan, implementation, wrapper, and Vectorize
mutation-quiescence approval. It allows a lost response to reconcile only the
exact already-active state and never permits a blind deployment retry. The
interruption checkpoint remains bound through later health/evaluation retries and is
retired only after the complete recovery state is durable. The three live
control files remain inode-and-byte pinned through use and are moved, fsynced,
and read back in authorization-first/checkpoint-last order. Any live checkpoint,
resume marker, or promotion marker blocks ordinary recovery regardless of a
completed filename. A process/power loss can separately leave the
field-gate lock and requires reviewed stale-lock reconciliation before retry.
The final proof requires:

- `pending_outbox = 0` and `failed_vectors = 0`;
- D1 documents and chunks equal the source aggregates sealed in the encrypted
  provenance artifact;
- FTS rows equal D1 chunks;
- every D1 chunk has one distinct vector ID, and the complete D1 ID set equals
  the complete provider Vectorize ID set with no extras or omissions;
- the provider's processed mutation watermark is stable and names the Worker's
  verified projection barrier before promotion and after active deployment;
- health reports v0.4.8, active mode, and accepting documents;
- the supported marker case returns at least one citation from the restored
  synthetic corpus; and
- the unsupported case returns the reviewed refusal with no unauthorized
  retrieval;
- every non-`llm_call_log` durable content and sequence byte remains unchanged
  across evaluation, while the bounded append matches the reviewed labels,
  model, call bounds, and time window, uses sequential IDs, advances only its
  matching SQLite sequence, and records nonnegative cost fields; and
- the source and final-target D1 deletion-state fingerprints are durable and
  bound to their exact resource identities.

HTTP success, a declining queue, or a completed adapter stage alone is not
parity proof.

final-target D1 deletion fingerprints. The fixed broker accepts only the two
