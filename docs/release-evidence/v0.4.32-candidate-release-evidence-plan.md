## Proof boundary

This version bump identifies the published 0.4.31 release plus one Google
Drive change and nothing else. A Drive changes page that holds one changed
file with no parent folder, with several parent folders, or with an unusable
file identity no longer stops every later Drive change. That one item is
settled on its own (outside the watched folders, scoped through its parents,
or recorded as a visible failure) and the rest of the page is read. There is no
new migration; the schema stays at 70. It supplies no release evidence,
incident closure, field acceptance or installation approval. The final
reviewed commit and sealed package must receive their own evidence. No
previous candidate's receipts transfer to this version.

The incident registry remains unchanged. Since the held 0.4.8
candidate, three acceptance texts changed and one row was added: UPDATE-006,
UPDATE-012 and UPDATE-025 changed, and UPDATE-044 was added. Against the last shipped
release, v0.4.6, five acceptance texts changed and two rows were added:
those rows plus UPDATE-043 and the UPDATE-036 and UPDATE-037 acceptance changes.
This plan grants no exact-version deferrals.

## Owner answer acceptance

Every owner question must receive the best answer supported by the available
records. A refusal or a wrong figure at High confidence blocks release.
Internally, every answer is still computed with a confidence level from the
data and the assistant may only lower it; owners do not see the word or
score. Below full support, the answer explains why and names the missing
evidence. Check the five parts: the figure and period first, account and date
coverage, missing or double-counted dollars, likely estimates and their basis,
and how to check.

Verify on the exact final package before claiming field acceptance: an update
from 0.4.29 and from 0.4.31 on a test Brain, then a Drive changes check on that
Brain with a changed file that has no parent folder, a file with two parent
folders, and an ordinary file in a watched folder. The changes position must
move on, the ordinary file must be read, and a later run must retry a file
whose folder metadata was repaired. Removal review decisions that are waiting
on a restore must survive a Drive settings change.

Known limits remain visible: rolling back an empty partial replacement poll
can leave its resume action unavailable (review B08); an older Brain command
that still uses the shared Windows lock folder is not excluded by the private
per-user lease; SimpleFIN evening purchases may land on the next UTC day;
acceptance trusts the Worker's own explanation fields. Two Drive limits are
new in this version: a folder whose trash flag Google returns in an unexpected
form can settle a file inside it as outside the watched folders, and a
restore that was refused can lose its error record across runs while its
restore obligation stays open. Those explanations are not independent proof of
correctness. Audit each supported figure against independent truth.

## Stop conditions
