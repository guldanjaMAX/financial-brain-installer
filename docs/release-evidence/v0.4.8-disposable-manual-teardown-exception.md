# v0.4.8 disposable manual teardown exception

- Status: proposed and unapproved
- Scope: one supervised synthetic disposable-recovery campaign only
- Provider activity: none
- General teardown implementation: still unavailable

## Decision

The preview-only teardown tool remains fail-closed. It must not gain an
automatic deletion path for this pilot. Cloudflare Worker and Vectorize deletes
are name-addressed, so a preview cannot make the final read-to-delete interval
race-free.

For this one synthetic campaign, that residual race is a low practical risk
only when every control below is met. The exception is an operator procedure,
not product functionality, production proof, or authority for a customer Brain.

## Exact scope

Only these already reserved synthetic campaign names may be considered:

- `brain-test-v048-field-source-recovery-gate-a48f1101`
- `brain-test-v048-field-target-recovery-gate-a48f1102`

The private campaign record binds the sole test account, exact Worker identity,
D1 UUID, Vectorize descriptor and creation identity, candidate commit, package
digest, wrapper bytes, provider bytes, and each approval. None of those private
identifiers belongs in this repository or a public receipt.

## Preconditions before the first campaign provider call

1. Seal the exact candidate and package and pass their offline, package,
   privacy, migration, and draft-PR CI gates.
2. Record the designated release owner's explicit acceptance of this exception
   and the remaining name-addressed deletion risk.
3. Prove the test account contains no client data and both reserved names are
   absent before provisioning. Never reuse either name after this campaign.
4. Use one short-lived least-privilege credential limited to the required
   read/create/update/delete resource classes in the sole test account. Ambient
   provider credentials remain refused.
5. Declare a private maintenance window with one operator. Pause CI, scheduled
   jobs, deployment tools, browser automation, and every other actor that could
   create, replace, rename, or delete resources in that account.
6. Run the preview-only teardown tool for each name and privately retain the
   exact account/resource identity hashes and reviewed wrapper/provider hashes.
7. Prepare a durable private mutation journal before any deletion. It records
   planned, sent-unconfirmed, confirmed, or reconciled status for each exact
   action without storing credential material.

Any unmet precondition keeps the whole field campaign held.

## Supervised deletion sequence

Source and target are separate ceremonies with separate approvals. Complete and
review the source ceremony before requesting target approval.

For each Brain:

1. Re-read the account, Worker, D1, and Vectorize resources immediately before
   deletion and compare every identity with the accepted private preview. Stop
   on a missing value, mismatch, changed descriptor, or concurrent activity.
2. Persist the exact Worker deletion as planned, then delete only the exact
   bound Worker name. Confirm absence before continuing.
3. Persist the exact D1 deletion as planned, then delete only the bound D1 UUID.
   Confirm exact UUID absence before continuing.
4. Persist the exact Vectorize deletion as planned, then delete only the exact
   bound Vectorize name. Confirm absence before continuing.
5. If a response is lost, times out, or is otherwise ambiguous, write
   sent-unconfirmed and reconcile with read-only provider calls. Never issue a
   blind retry or reinterpret an unknown result as success.
6. Require exact provider absence for all three resources, then rerun the
   preview-only tool and require all three kinds to report absent.

No account list omission substitutes for the exact identity check. No source
approval authorizes target deletion, and no deletion approval authorizes release
or any other provider mutation.

## Closeout

Retain the private campaign receipts and aggregate public proof before removing
local campaign material. Delete only the three campaign-specific Keychain items
after exact provider absence is confirmed and the retention decision is
approved. Verify the shared test-account credential remains intact without
printing it.

The exception passes only when both Brains have complete planned-to-confirmed
mutation journals, exact absence proof, repeated absent previews, no ambiguous
action, and no concurrent actor. Otherwise cleanup remains open and the field
campaign cannot support the next evidence rung.

## Explicit non-precedent

This exception does not make `scripts/teardown-test-brain.mjs --commit`
available. It does not prove an uninstall path, customer offboarding, production
resource deletion, account-wide cleanup, or general release readiness. A future
product teardown still needs its own reviewed authority and provider-race design.
