  closed. ADR 008 defines the narrowed scope.

## Candidate feature acceptance focus

The 0.4.25 candidate contains the integrated changes since the 0.4.24 source.
Acceptance must exercise final behavior rather than superseded lane proposals:

1. **Everyday money routing and definitions.** Exercise account shorthand,
   pending and uncleared card/account questions, shared dates, owner-local
   periods and event wording. Definitions without an owner-record request
   must return to documents before extraction. Preserve the deterministic
   parser and closed model validation. Independent periods, dates, amounts,
   selectors, payees and outer tasks must still reach their refusal or
   clarification decisions beside green controls.
2. **Answerable cores and detail limits.** Exercise requests for rows,
   freshness, account details, recurring-charge analysis and exact-amount
   payment candidates. Preserve the verbatim unanswered part, actual account
   scope, interpretation, direction and source citations. Synthetic examples
   cannot prove that a fresh model will recover earlier refusals. Repeat that
   assessment separately on the final package before claiming improvement.
3. **Reader amounts and membership.** Verify posted/pending qualification,
   direction before limits, transfer-pair counts, recurrence dates and
   per-account rankings. Prove explicit same-period expenses less refunds,
   payee refund disclosures, category-first remainder membership and exact
   cents. Unknown selectors must never turn into zero or an invented balance.
4. **Softer refusals across surfaces.** Inspect the app, CLI and MCP for an
   opening that says what the Brain can give, a plain evidence gap and one
   next step. Preserve partial/unconfirmed labels, coverage limits, temporal
   uncertainty and citations. Cash-flow and forecast requests must not gain
   invented figures. Check the rebuilt embedded frontend against its source.
   Exact scorer translations must reject changed cents and unsupported copy.
5. **Optional contacts and D1 provider checks.** Fresh setup and init omit an
   unknown contact; existing empty optional contact strings pass validation.
   Absent and valid contacts are green controls. Nonempty malformed values,
   required fields, types and minimum lengths retain their decisions. Verify
   all twelve ledger tables in the state read and both transition guards,
   bounded SQL compound terms and the fixed cause codes. Preserve the known
   in-flight connection warning; this is not general bank acceptance.
6. **Field-specific legacy-model update.** Exercise both legacy fields,
   mixed reviewed/legacy choices and missing/null inherited fields. Announce
   and change only fields using the retired model while retaining the stored
   key, daily cap and selected peer. Interrupt after possible deployment and
   before local commit: saved bytes stay intact, the retry notice names the
   possible remote change, and retry must finish. Malformed or unreviewed
   IDs still refuse after reaching the model decision.
7. **Inherited 0.4.24 behavior.** Repeat vendor-family, period-comparison,
   monthly-breakdown, account-kind review, repayment, scheduler rebinding,
   curated readback, meeting-export and explicit-deletion acceptance where
   affected. Migration 0058 remains the account-kind review boundary. No prior
   field receipt transfers to the new package bytes.
8. **Integrated regression and privacy.** Repeat current-version, owner-rule
   hash, package privacy, update audit and every affected suite. Daily CLI
   suites must preserve the ambient home canary while using isolated homes.
   Extracted deploy fixtures must supply the current update manifest binding.
   Recorded model tapes, synthetic cases and earlier host results do not
   certify live answer correctness. Private replay inputs stay outside product
   source and the distributable package.

## Known issues and supervised-update precautions

- A failed bank-document replacement after a committed import or account change
  can leave stale bank documents until the scheduled retry.
- Own transfers between non-USD accounts can remain in money-in or money-out
  figures.
- Do not switch bank providers while a bank connection is in progress. A
  request already crossing the transition can write after the transition
  clears.
- A very large ledger can return `query too large` instead of an answer.
- This candidate has no account-link recovery command.
- A Windows daily refresh still skips the day when its lifecycle lock is busy.
- The local bank-provider manifest validator does not enforce every schema
  string format.
- After a failed `brain update`, run `brain health`. The inherited
  pause-ambiguity and unconfirmed-migration messages still need verification
  against the exact sealed package rather than carrying forward earlier proof.
- Verify that a private rollback bookmark receipt was durably saved before
  deployment or migration in the separately authorized update campaign.
  Interrupted-update recovery still needs its own acceptance evidence.
- Review money totals against cited rows, dates, currency, account coverage,
  possible transfers and visible gaps. This planning record authorizes no live
  update and provides no field proof.
