## Superseded historical decision

At the time of this abandoned proposal, the preview-only teardown tool was
fail-closed. The proposal did not authorize adding an automatic deletion path.
Cloudflare Worker and Vectorize deletes were name-addressed, so that preview
could not make the final read-to-delete interval race-free.

The never-approved proposal treated that residual race as a low practical risk
only if every control below were met. It was not product functionality,
production proof, or authority for a customer Brain.

The abandoned proposal would have required all of the following. These are not
current instructions and must not be used as an operator checklist.

1. Seal the exact candidate and package and pass their offline, package,
   privacy, migration, and draft-PR CI gates.
2. Record the designated release owner's explicit acceptance of this exception
   and the remaining name-addressed deletion risk.
3. Prove the test account contains no client data and both reserved names are
   absent before provisioning. Never reuse either name after this campaign.
4. Use one short-lived least-privilege credential limited to the required
   read/create/update/delete resource classes in the sole test account. Ambient
   provider credentials remain refused.
5. Declare a private maintenance window with one operator. Pause CI, scheduled
   jobs, deployment tools, browser automation, and every other actor that could
   create, replace, rename, or delete resources in that account.
6. Run the preview-only teardown tool for each name and privately retain the
   exact account/resource identity hashes and reviewed wrapper/provider hashes.
7. Prepare a durable private mutation journal before any deletion. It records
   planned, sent-unconfirmed, confirmed, or reconciled status for each exact
   action without storing credential material.

Any unmet precondition keeps the whole field campaign held.

## Superseded deletion sequence, never execute

The abandoned sequence proposed separate source and target ceremonies and
separate approvals. It proposed completing and reviewing the source ceremony
before requesting target approval.

For each Brain, it proposed the following obsolete order:

1. Re-reading the account, Worker, D1, and Vectorize identities against the
   accepted private preview.
2. Journaling and deleting the exact Worker, then confirming absence.
3. Journaling and deleting the bound D1 UUID, then confirming absence.
4. Journaling and deleting the bound Vectorize name, then confirming absence.
5. Recording and reconciling an ambiguous response without a blind retry.
6. Requiring exact provider absence for all three resources and rerunning the
   old preview-only tool.

That order is obsolete. The current fixed broker requires Worker, Vectorize,
then D1, with a fresh D1 deletion-state proof immediately before D1 deletion.
Only the current field plan and installed broker describe the held path.

No account list omission substitutes for the exact identity check. No source
approval authorizes target deletion, and no deletion approval authorizes release
or any other provider mutation.

## Closeout

Retain the private campaign receipts, exact package and controls, encrypted
provenance artifact, and aggregate proof. The implemented A17 contract may
delete only the four campaign-specific Keychain items after exact provider
absence is confirmed and the retained-evidence inventory is approved. It must
verify the shared test-account credential remains intact without printing it.
A17 is implemented offline and locally fixture-tested, but remains held,
unfielded, and uncertified. It has no field or live proof and grants no release
authority. This historical exception does not authorize it or provide a
fallback closeout.

The exception passes only when both Brains have complete planned-to-confirmed
mutation journals, exact absence proof, repeated absent previews, no ambiguous
action, and no concurrent actor. Otherwise cleanup remains open and the field
campaign cannot support the next evidence rung.
