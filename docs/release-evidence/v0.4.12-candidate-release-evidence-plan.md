## Exact-version deferral renewal

This record renews only the two already documented scopes for 0.4.12. It does
not change either incident's status or acceptance criteria.

- **UPDATE-012:** Physical Windows ARM64 hardware with Node 24 remains
  unavailable. Hosted x64 CI cannot supply the packaged-launch, DPAPI, browser
  login, interrupted-update, clean-exit, or printed-command identity proof the
  acceptance requires. Windows x64 remains the only claimed Windows runtime,
  and Windows ARM64 ships unproven in 0.4.12. ADR 007 defines the re-homed
  acceptance scope.
- **UPDATE-044:** The acceptance requires live accounts at two institutions
  and at least four accounts spanning a person and two businesses, including a
  real business banking login. Synthetic and sandbox evidence cannot establish
  that breadth. Bank breadth ships unproven in 0.4.12, and bank invitations
  stay closed while this deferral stands. ADR 008 defines the narrowed scope.

If accepted evidence from the sealed package closes either row before a
release write, the closure change must remove that row's deferral. No other
deferral is renewed by this plan.

## Candidate feature acceptance focus

The 0.4.12 changelog adds the following acceptance focus:

- Ledger balances, exact deposits, income and spending, merchant and category
  totals, largest expenses and recurring-charge estimates retain row citations,
  literal account masks, reviewed categories and explicit coverage gaps.
- Manual exports retain stable transaction identity across reordered rows.
  Account links, unlinking and legacy re-key pages require exact reviewed
  plans. Live-feed precedence applies only inside owner-linked coverage;
  account collisions, uncertain overlaps and loan duplication remain guarded.
- Possible own-account transfers stay included and are separately labelled for
  review. AI-authored notes cannot be sole money evidence; dated primary
  documents without lineage remain eligible but cannot prove independent
  confirmation. Figure, month, account and date mismatches refuse money claims.
- Retrieval respects explicit document dates, reduces backup copies, tries
  conservative spelling alternatives, dates status observations and retains
  only cited list items. Date repair remains previewed operator maintenance.
- Tax evidence checklist requests explicitly select one entity and year. The
  checklist separates missing evidence, unavailable reads, extraction limits
  and review steps. It does not check tax amounts or filing readiness; typed
  questions remain ordinary Ask.
- Source inventory and refresh histories use bounded pages. Daily freshness
  can remain unknown while eligible work proceeds, held sources stay held,
  and quiet provider checks retain evidence separate from ingest dates.
  Gmail finalization retries stay bounded and unresolved messages stay visible.
- Curated collections support a reviewed Cloudflare-only path. Update pause
  ambiguity and unconfirmed database changes give honest recovery guidance.
  Updates persist and verify rollback bookmarks before deployment or migration,
  with platform-specific permission checks.
- Machine Prep handles standard Windows Node paths, checks npm layout and
  preserves accessible, redacted failure logs without overwriting earlier logs.

QuickBooks Desktop connection, custody, refresh and ingest still require
separately reviewed field acceptance before money-answer or owner-readiness
claims. Financial contracts, the test-only oracle, books-match and tax-check
remain internal libraries. SimpleFIN proof remains held. The Machine Prep
installer and sealed-kit pins remain unchanged until separately sealed and
reviewed; this version bump does not rebind those artifacts.

Local tests establish deterministic behavior only. Provider, operating-system,
and live-account claims require their separately authorized gates.
