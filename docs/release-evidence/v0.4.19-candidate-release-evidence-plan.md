## Exact-version deferral renewal

This record renews only the two already documented scopes for 0.4.19. It does
not change either incident's status or acceptance criteria.

- **UPDATE-012:** Physical Windows ARM64 hardware with Node 24 remains
  unavailable. Hosted x64 CI cannot supply the packaged-launch, DPAPI, browser
  login, interrupted-update, clean-exit, or printed-command identity proof the
  acceptance requires. Windows x64 remains the only claimed Windows runtime,
  and Windows ARM64 ships unproven in 0.4.19. ADR 007 defines the re-homed
  acceptance scope.
- **UPDATE-044:** The acceptance requires live accounts at two institutions
  and at least four accounts spanning a person and two businesses, including a
  real business banking login. Synthetic and sandbox evidence cannot establish
  that breadth. Bank breadth ships unproven in 0.4.19, and bank invitations
  stay closed while this deferral stands. ADR 008 defines the narrowed scope.

If accepted evidence from the sealed package closes either row before a
release write, the closure change must remove that row's deferral. No other

## Candidate feature acceptance focus

The 0.4.19 candidate integrates optional Claude answers, setup-aware assistant
routing and update fail-safe work. Acceptance must exercise the final
integrated behavior, not superseded lane proposals:

1. **Optional Claude answers.** Connect a synthetic owner-custody Anthropic key
   through the reviewed hidden-input path. Prove Opus writes an answer, Sonnet
   checks it, multi-block replies are read completely, provider details stay
   private, and built-in answers remain unchanged when no pair is selected.
2. **Daily limit and recovery.** Verify the recommended $5 daily limit, exact
   provider-family charging, timeout charging, typed pause and reset receipts,
   rollback after every failed connection stage, and recovery that retains the
   previous reviewed model pair. No test value may enter argv, logs or source.
3. **Setup-aware assistant routing.** A configured Claude pair must ask for the
   Brain's own checked answer first. A built-in Brain must search, read the
   excerpts and then answer. Broad requests stay record by record, report
   unchecked scope, and cannot derive totals or completeness from excerpts.
4. **Search-scoped absence.** A healthy empty result must trigger a second
   differently worded or newest-sorted search. The assistant may name both
   searches and the next place to check, but may not infer global absence from
   one or two ranked searches. Provisional and unavailable searches retain
   their stronger refusal contract.
5. **Windows pasted key.** Exercise the native secure paste path, its single
   terminal line-ending normalization, clipboard-clear result and interior
   newline refusal. Existing model bindings and secret rollback must remain
   exact after every failure.
6. **Migration plan boundary.** Refuse unreadable, unknown, duplicate,
   malformed or gapped migration history before bookmark capture, pause,
   deployment or schema write. Print and verify the complete ordered pending
   range before entering the pause boundary.
7. **Answer-aware acceptance.** When an answer model is configured, acceptance
   requires nonempty answer text, the exact model receipt and the required
   Worker secret-name inventory. Built-in clean degradation retains its prior
   verdict without inventing an external-model requirement.
8. **Lock and version honesty.** Lock contention must name the holding
   operation, start time and retry action. Reaping requires confirmed dead or
   reused process identity. A recorded schema version below the durable ledger
   maximum must identify the older-tool regression and route through the
   supported update command.
