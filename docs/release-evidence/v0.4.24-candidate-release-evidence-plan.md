  closed. ADR 008 defines the narrowed scope.

The release note keeps both limitations visible to the owner. No deferral is

## Candidate feature acceptance focus

The 0.4.24 candidate contains the integrated changes since the 0.4.23 release.
Acceptance must exercise final behavior rather than superseded lane proposals:

1. **Everyday money routing.** Exercise shorthand, account nicknames, payer
   wording, category words, recent payments and vendor questions through the
   real question path. Preserve deterministic parsing first, validate the
   closed model response, and keep document decoys outside the ledger. Prove
   the bounded timeout, fenced JSON and failure behavior with green controls.
2. **Periods and event wording.** Verify owner-local years, quarters, months,
   single days, relative ranges, two-period comparisons and monthly breakdowns.
   Date text must outrank model-supplied period guesses. Unknown events must
   disclose the earliest covered date without inventing an event date.
3. **Accounts and answerable parts.** Exercise balance kinds, cash-only and
   account-type balances, own-account comparisons, unmatched account hints,
   freshness and share-of-total additions. Prove the interpretation label,
   actual account scope and verbatim unanswered part stay visible. A broader
   reading must never look like a resolved account nickname.
4. **Vendor families and transfers.** Verify whole-word family membership,
   bounded aliases, ambiguous short-name exact controls and per-payee amounts.
   Description-only possible matches stay outside totals. Matched transfers
   consume each row once, and unsupported currency pairs retain their limits.
5. **Plain refusals and dates.** Inspect the rendered balance, coverage,
   scanned-evidence, account-link and MCP absence answers. Each refusal names
   what could not be answered, why and a supported next question. Preserve
   exact coverage warnings, readable dates and independent negative controls.
6. **Legacy answer-model update.** Start with the exact older
   `claude-sonnet-5` model, announce the switch to `claude-opus-5-5` answers and
   `claude-sonnet-5-5` checks, retain the stored key and daily cap, and verify
   both models through the supported update. Interrupt before completion and
   prove the saved model fields are unchanged. Malformed values and other
   unreviewed IDs must still refuse after reaching the model decision.
7. **Inherited 0.4.23 behavior.** Repeat account-kind review, repayment,
   scheduler rebinding, curated readback, meeting-export and explicit-deletion
   acceptance where affected. Migration 0058 remains the account-kind review
   boundary. No prior field receipt transfers to the new package bytes.
8. **Integrated regression and privacy.** Repeat current-version, owner-rule
   hash, package privacy, update audit and every affected suite. Daily CLI
   suites must preserve the ambient home canary while using isolated homes.
   Recorded model tapes, synthetic cases and earlier host results do not
   certify live answer correctness. Private replay inputs stay outside product
   source and the distributable package.

## Known issues and supervised-update precautions

- A failed bank-document replacement after a committed import or account change
  can leave stale bank documents until the scheduled retry.
- Own transfers between non-USD accounts can remain in money-in or money-out
  figures.
- Do not switch bank providers while a bank connection is in progress. A
  request already crossing the transition can write after the transition
  clears.
- A very large ledger can return `query too large` instead of an answer.
- This candidate has no account-link recovery command.
- A Windows daily refresh still skips the day when its lifecycle lock is busy.
- The local bank-provider manifest validator does not enforce every schema
  string format.
- After a failed `brain update`, run `brain health`. The inherited
  pause-ambiguity and unconfirmed-migration messages still need verification
  against the exact sealed package rather than carrying forward earlier proof.
- Verify that a private rollback bookmark receipt was durably saved before
  deployment or migration in the separately authorized update campaign.
  Interrupted-update recovery still needs its own acceptance evidence.
- Review money totals against cited rows, dates, currency, account coverage,
  possible transfers and visible gaps. This planning record authorizes no live
  update and provides no field proof.
